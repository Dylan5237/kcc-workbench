## 1. 第一性原理：拆到不可再分

### 1.1 原子问题

剥掉所有功能，Arckeep 解决的是一个并且是唯一一个问题：

> **再进入成本。** 每次回到一项工作，都要付出上下文重建成本——想起做到哪、为什么这样做、接下来做什么。Arckeep 把这个成本压到最低，并且**诚实地**压（不能用系统的猜测冒充事实来制造"便宜"的假象）。

### 1.2 七条原子真理

| # | 原子 | 含义 |
| --- | --- | --- |
| A1 | **项目即目录** | 项目是磁盘上的一个工作目录。Arckeep 的项目数据也该住在那里，可检查、可备份、随目录迁移 |
| A2 | **事实与理解分离，理解带证据分级** | 文件系统和 Git 是事实；状态、待办、判断、摘要是理解。理解必须携带：来源、谁写的（你/系统）、认知状态（推测/确认/已取代/过期/忽略）。证据分五级：观察（文件系统）/ 状态（Git 某时刻读数）/ 陈述（agent 原话，未核实）/ 推测（系统）/ 确认（用户）——级别之间不得互相冒充 |
| A3 | **采用与确认分离** | 使用是操作，确认是认知。采纳一条推测去继续工作 = 本轮采用（操作态，零认知权重）；只有用户改写（成为作者）或现场显式确认，才升格为确认。系统不需要被审阅，需要被使用；不被使用的推测自行过期 |
| A4 | **返回即触发，但不是证据** | 可靠的事件不是"agent 说自己结束了"，而是"用户回来了"。返回只触发回流检查（读文件系统差异 + 读会话 API 状态）；返回 ≠ 会话结束，观察到变化 ≠ agent 完成 |
| A5 | **上下文即简报** | 跨越 agent 边界的耐用通道只有一种：文本。自动生成的简短简报（状态 + 接续点 + 判断索引 + 变更文件）经 agent 的开场消息或 context.md 交付；交付状态必须诚实（已生成 ≠ 已交付） |
| A6 | **注意力有预算** | 首屏只回答两个问题：现在在哪、下一步是什么。其余一切一次点击可达。预算以屏幕面积计，不以功能数计 |
| A7 | **Agent 可替换，协议先行** | 接入深度分级（L1–L4），每级诚实声明能力边界，不为表面一致改造任何 agent |

### 1.3 重推的必然结果

- 状态/待办/判断/摘要都是"理解"（A2）→ 存储自带来源、认知状态与证据级别，且住在项目目录里（A1）→ `.arckeep/` 布局（§5）。
- "用户确认"如果是独立任务就会疲劳衰减（DR-02 命中）→ 可持续模型是 A3：采用零成本、确认在现场单击完成、不用即过期。**不设确认收件箱**——用新注意力负担管理旧注意力负担，违反 A6。
- "会话结束事件"不可靠（DR-03 命中）→ A4：返回触发回流检查；结束是另一个独立事实，有自己的判定（§3.3）。
- 上下文面板 stakes 过高（DR-01 命中）→ A5 降权：默认简报自动最小，面板从闸门降为可选调整。

## 2. 对两轮审查的裁决

### 2.1 第一轮（对抗性审查报告，18 条）

报告最重要的贡献是**信任链簇**的识别：系统生成 → 用户确认 → 成为当前认知 → 进入下次会话，这条链是 Arckeep 区别于"又一个 agent 启动器"的全部价值。判断成立。裁决统计：12 条直接采纳、4 条采纳问题但改写解法、2 条部分采纳；DR-02 的"确认收件箱"解法被驳回（违反 A6）。逐条对应关系见 git 历史中的 v0.3 初稿 §2.2。

### 2.2 第一轮审查漏掉、第二轮补上或仍有效的三个问题

1. **项目创建流程**：指向目录即项目（§4.0）。
2. **简报的最后一哩**：交付必须留下可核查证据（M1）。
3. **并发会话边界**：一项目一活跃接入会话 + 锁机制（D-34，M4.4）。

### 2.3 第二轮评审的总判断

评审结论（产品方向通过 / 机制有阻断缺口 / 工程开工条件未满足 / 仓库实现未对齐）**全部接受**。本文档中的"已确认"只表示设计决策已定，**不表示运行时能力已存在**；当前仓库（Electron v1）没有任何 Brief 生成/注入链路、没有 `.arckeep/`、时间机器快照存在应用数据目录——文档与实现对齐是 2.0 开发的任务本身。

### 2.4 第二轮逐条裁决

## 3. 五个核心机制规格

### 3.1 M1 · 上下文简报（Brief）

**默认内容（自动最小，相关性先行）：**

1. 用户**显式选中的接续点**原文（这是任务本身）；
2. 当前状态一句话（项目内定义，天然项目范围）；
3. 当前有效关键判断的**索引**（标题一行 + 指向 `.arckeep/decisions.md` 的路径；agent 按需读正文，不默认注入 payload——"已确认"不等于"当前相关"）；
4. 自上次会话以来观察到的变更文件清单（前 10 条，标注为"观察"）。

体量目标 ≤400 字（T），超出时截断**且列出被截掉的项**——截断规则透明，不做不透明排序。除此之外的任何内容必须经"调整携带内容"由用户显式加入。

**交付通道（按接入级别）：**

| 级别 | 通道 | 交付证据 |
| --- | --- | --- |
| L4/L3 CLI 类（Claude Code / Codex） | 新会话初始 prompt 参数携带简报 + 写 `context.md` | 进程退出码 + 会话 transcript 中含简报文本 |
| L3 Kimi Code | **ACP（spike 已验证，0.39）**：`session/new`（带 cwd）+ `session/prompt`（携带简报）；Web UI 仅作嵌入视觉平面（D-20） | ACP `sessionId` + `stopReason` + 流式 transcript 事件 |
| L2 | 写 `.arckeep/context.md`，启动时告知读取 | 无送达证据，状态只能是"已生成" |
| L1 | 不交付，仅登记 | — |

**交付状态机（侧轨只显示真实状态）：** `已生成`（写了 context.md，永远可达）→ `已交付`（有上表证据）/ `未送达`（证据缺失或通道失败，明示并给出降级动作）。**任何情况下"已生成"不得显示为"已交付"。**

**`context.md` 语义：** 头部元信息含 `version、writtenAt、targetSessionId、briefHash`；一次性语义——新会话开始时生成新一份即覆盖旧的，历史简报进 `history/`；agent 读到的永远是最新一份。

### 3.2 M2 · 确认模型（采用与确认双轴）

**两个独立的轴：**

- **操作态**（本轮采用 / 未采用）： ephemeral，只影响"这次带什么去工作"，零认知权重，本轮结束即清。
- **认知态**（推测 / 确认 / 已取代 / 已过期 / 已忽略）： 持久，决定"这条理解是否支配现在"。

**认知态状态机：**

```text
推测（系统生成，带来源与 expiresAt，TTL 14 天 (T)）
  ├─ 被选中/被采用      → 仍是推测（标"本轮采用过"），不升格
  ├─ 被用户编辑改写     → 确认（用户成为作者）
  ├─ 现场单击"确认"     → 确认（附着在使用点，不进队列）
  ├─ 被忽略（dismiss）  → 已忽略，归档 history/
  └─ 超过 TTL 未被使用  → 已过期，归档 history/
确认
  └─ 被新判断取代       → 已取代（默认折叠为计数，点击展开，永不删除）
```

- 来源标注口语化："我猜的 · 来自昨天与 Codex 的会话"。
- 状态句陈旧提示：`updatedAt` 超过 7 天 (T)，元信息行追加"可能已过期，建议你重写一句"。
- 负荷自限：每次回流最多产生 2 条 (T) 推测候选。
- **所有 (T) 阈值为暂定工程起点**，经真实使用数据校准前不视为已确认值。

### 3.3 M3 · 返回、结束与回流（证据分级）

**三个不得混淆的事实：**

| 事实 | 判定来源 | 标签 |
| --- | --- | --- |
| 用户返回 | 窗口焦点/切屏/按钮 | — |
| 会话结束 | agent 进程终止 / 会话 API 报告 / 用户显式结束（三者其一）；**返回不在其中** | — |
| 文件变化 | 文件系统 diff（无归因） | 观察 |

**证据分级标签（UI 与存储一致使用）：** 观察（文件系统变化）/ 状态（Git 某时刻读数）/ 陈述（agent 原话，未核实）/ 推测（系统摘要候选）/ 确认（用户确认过的理解）。

**回流触发（任一，走同一管道）：** ① 从接入态切回项目空间；② 侧轨"回到项目"按钮；③ 应用窗口重新获得焦点且存在活跃会话。

**回流检查动作与更新矩阵：**

| 区块 | 回流后行为 | 标签 |
| --- | --- | --- |
| 最近产出 | 立即刷新 | 观察 |
| 会话现场 | 更新为原始摘录，标注 agent 与时间 | 陈述（未核实） |
| 会话摘要 | 系统起草候选进入 Session Map 节点 | 推测 |
| 可能值得继续的事 | 最多 2 条 (T) 候选 | 推测 |
| 关键判断 | **从不自动**；摘要候选可附"疑似新判断"提示 | — |

**会话生命周期（独立字段，不与认知态混用）：** `进行中 / 已结束 / 仍在后台运行 / 失联`。返回时会话仍在运行 → 侧轨显示"会话仍在进行中"，回流只读文件系统，不起草摘要。

### 3.4 M4 · 自有数据存储：`.arckeep/` + workspace 模型

**身份模型（裁决第二轮 #4）：项目 ≠ 目录，项目 = 长期身份；目录 = 项目的工作区实例。**

- `projectId`：稳定随机 ID，项目的长期身份；
- `workspaceId`：一个目录实例的 ID。主目录是默认工作区；Git worktree 分叉 = **同一项目的新工作区**（新 workspaceId，记录 forkedFrom，本地状态从零开始 + 指向来源项目）；
- 应用数据目录存项目注册表（projectId ↔ 各 workspaceId ↔ lastKnownPath）。目录被移动/复制导致 path 与注册不符时，自愈重发 workspaceId 并记录；目录丢失时项目显示"位置未知，请重新指向"。

**布局：**

```text
工作区目录/.arckeep/
  project.json       { projectId, name, createdAt }
  workspace.json     { workspaceId, projectId, path, forkedFrom?, createdAt }
  status.md          # 开场白 + 元信息（confirmedBy, updatedAt）
  next.md            # 值得继续的事（认知态/来源/expiresAt/操作态标记）
  decisions.md       # 关键判断（认知态/来源/范围/confirmedAt）
  sessions.json      # SessionNode[]（五轴分离，见 §5）
  context.md         # 最近一次简报（M1 语义）
  time-machine.json  # 检查点索引（commit、文件清单、指向快照的引用）
  history/           # 过期/忽略/已取代的归档（可查，不在场）
```

**数据分类（裁决第二轮 #5）：**

| 类别 | 内容 | 位置 |
| --- | --- | --- |
| 随目录迁移 | project/workspace 身份、status、next、decisions、sessions 索引、context、time-machine 索引、history | `.arckeep/` |
| 应用本地（可重建缓存） | 快照内容 blob、日志、额度缓存、viewer 诊断 | 应用数据目录 |

"复制目录即备份"只对第一类成立——文档与文案都必须写明这条边界。

- 纯文件、人类可读：理解类 Markdown，索引类 JSON；原子写入 tmp+rename；不修改用户 `.gitignore`（是否纳入版本控制由用户决定，文档给出建议与隐私提示）。
- 全局回退：目录不可写或用户不愿污染时，可设置存到应用数据目录。

### 3.5 M4.4 · 单会话锁（D-34 机制化）

- 锁存于**机器本地**（应用数据目录），不进 `.arckeep/`：`{ ownerSessionId, processId, heartbeatAt }`。
- 心跳间隔 15s (T)；心跳超过 60s (T) 未更新且进程不存在 → 锁可收回，下次打开提示"上次会话未正常结束，已收回"。
- 切换 agent = 先跑回流检查 → 结束当前接入 → 接入新 agent；MVP 不支持"保留后台运行再开一个"。
- 第二个应用实例打开同一项目：项目空间只读 + "已被另一窗口占用"提示，不允许接入。
- 手动"回到项目" **≠** 结束会话；结束动作显式存在。

### 3.6 M5 · 敏感信息边界

- 摘要、会话索引、快照落库前经 secrets 模式过滤（key/token/私钥形态）。
- 时间机器快照沿用文件类型白名单与数量上限（继承 v1：.md/.html/.json/.mmd，会话 20 / 检查点 40），淘汰窗口写入 PRIVACY 承诺。
- 诊断日志永不记录 token、cookie、会话正文。

## 4. 四屏信息架构（继承与修订）

### 4.0 前置：项目的诞生

指向一个目录 → 项目即存在：创建 `.arckeep/`，落点进入项目空间空态。创建时告知："我们会在项目里建一个 `.arckeep/` 文件夹存放工作状态，你可以随时查看或删除它"。无向导、无表单。

### 4.1 屏 1 · 项目空间

继承 v0.2 §3.1 信息结构，修订：

1. 可能值得继续的事：hover 出现"忽略"；推测条目带 TTL 与"我猜的"口语来源；选中 = 本轮采用（操作态），不升格认知态（M2）
2. 关键判断：已取代默认折叠为"历史 N"计数，点击展开
3. 启动区：「开始」直接以默认简报进入；「调整携带内容」为次要入口（M1）
4. 空态保留引导文案；状态句超龄显示陈旧提示（M2）

### 4.2 屏 2 · Session Map

继承 §3.2 结构与分叉边界（D-21 不动）。规模假设 ≤20 节点（T）；超出自动切换为按月分组列表（D-32）。详情区为摘要候选提供一行"确认这段摘要"（M2）。

### 4.3 屏 3 · 产出（完整 Viewer）

继承 §3.3 全部能力。补空态（无产出 / 非 Git 目录时时间机器降级说明）。性能约束移交 §7。

### 4.4 屏 4 · 接入态

继承 §3.4（D-20 不动）。修订：侧轨"本项目"块显示简报交付状态（已生成/已交付/未送达，M1）；"接回项目"是三触发之一（M3）；会话仍在运行时显示真实生命周期状态。

### 4.5 空态与降级态最小集

每屏至少定义：无数据空态（引导文案）、来源不可用降级（标注"会话信息暂不可用"并显示文件系统可提供部分）、错误句（一句人话 + 一个可执行动作）。不允许无文案空白区。

## 5. 数据模型 v0.3.1（五轴分离）

理解类条目（status / next / decisions / summary）统一字段：

```text
{
  id, text,
  epistemic: '推测' | '确认' | '已取代' | '已过期' | '已忽略',   // 认知态
  adoption:  '未采用' | '本轮采用',                              // 操作态，会话级
  evidence:  '观察' | '状态' | '陈述' | '推测' | '确认',          // 证据级别（A2）
  sourceRef: { type: 'session' | 'file' | 'git' | 'user', ref: string, at: timestamp },  // 结构化来源，非自由文本
  author:    'user' | 'system',
  expiresAt?: timestamp                                          // 推测必有
}
```

SessionNode：

```text
{
  id, projectId, workspaceId,
  agent, startedAt, endedAt?,
  relation:  'root' | 'continuation' | 'fork',     // 拓扑关系（fork 不再是确认状态）
  lifecycle: 'active' | 'ended' | 'background' | 'lost',  // 生命周期
  summary:   { text, epistemic, evidence:'推测'|'确认', sourceRef },
  parentId?: string
}
```

`Project.id` = projectId（稳定随机），`rootPath` 降为各 workspace 的属性（M4）。

## 6. 视觉语言（品牌 v1.0 融合）

本节取代 v0.2 §2。**权威来源是 `docs/brand/`**；本节只做产品语义映射，不重新定义品牌值。视觉稿 v0.4 是视觉参照实现，**不作为交互验收证据**（其交互为 toast 占位）。

### 6.1 色板语义映射

| 品牌色 | 产品语义 |
| --- | --- |
| Deep Charcoal `#232323` | 品牌面（侧栏）、主操作、当前判断标签、关键边界 |
| Warm Ivory `#F5F2EA` | 主工作面 |
| Olive `#5B5E3B` | 正向系统状态（实时/新增/选中节点），永远伴随文字 |

| Soft Stone `#D8D4CB` | 分隔线、边框、静默面 |
| Muted Graphite `#66635D` | 次级文字（语义级小字统一用此色，不用更浅的 #7A756D） |
| 功能红 `#8E3C32` | 删除与危险 |

### 6.2 字体与文字

产品 UI 全面无衬线，字重 Regular/Medium/Semibold；等宽只承载事实（文件名/时间戳/编号/页码）；品牌字标禁止用字体重排；"续境"与品牌语按命名规则节制使用。

### 6.3 图形母题与组件

Open Cut（页眉细线不到边 + 45° 切面；主操作按钮右下 7px 切角）；连续性折线仅现于品牌面；哑光平面，无渐变/投影/纹理；圆角 ≤2px；层级由间距、字重、对齐建立。

### 6.4 动效

micro 120–220ms；状态接续 220–360ms（切屏 = 淡入 + 微位移）。禁止弹跳炫技。

### 6.5 布局预算与可访问性（D-28，修订）

- **页面级不滚动；内容窗格可滚动**（Viewer 列表、长内容区）。两个规则不再打架
- 首屏一屏回答两个问题：目标 1920×1080；底线 1366×768 @100% DPI 完整可见
- 最小窗口与最小内容区显式定义（主内容区 ≥ 720px 宽）；窗口小于底线时允许窗格滚动，不允许内容无声裁切
- DPI 125%/150% 与 Windows 文本放大：窗格内自适应，首屏两问保持完整
- WCAG 2.2 AA 对比度；焦点可见；全键盘可达；状态永不单独依赖颜色
