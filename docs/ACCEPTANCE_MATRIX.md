# KCC Workbench 公开验收矩阵

> 用途：把“能跑”“看起来没问题”升级为可复核的证据。每个能力都标注验证层级，避免把代码路径验证与真实环境验收混为一谈。

## 验证层级说明

| 层级 | 含义 | 典型方式 |
| --- | --- | --- |
| **L1 代码路径** | 隔离环境下的逻辑与回归 | `npm test`、Viewer 样例、打包结构测试 |
| **L2 打包验证** | 构建链与产物完整性 | `npm run build` / `npm run pack`、产物大小与哈希、依赖闭包 |
| **L3 真实验收** | 需要登录、真实会话或真实网络 | 登录 Kimi / Claude / Codex、CloudCLI 会话目录同步、真正登录后的 Viewer 跟随 |

## 备注

- “▶ 打包”表示该能力在真实会话里已验证，但打包后的 zip 产物环境尚未逐项复验。
- 真实验收需要登录环境，无法在无账号的 CI 中复现；本矩阵不把 CI 绿当成“真实验收已通过”。
- 每次发布应在 Release 说明中声明本次覆盖的层级与证据。

## 维护方式

- 每次改动后运行 `npm test`。
- 影响打包或运行时的改动运行 `npm run build`。
- 发布前核对本矩阵，新增能力时补一行并记录验证方式。
