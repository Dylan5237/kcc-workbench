## Goal

Restore KCC 1.0 Viewer realtime behavior so the 5-day dogfood can use the existing `Agent -> Viewer -> review` loop without manual refresh/debugging.

## Scope discipline

This is a bug repair, not Viewer redesign.

Do not add Arckeep Project features, DSH, cdesktop, new navigation, a new watcher framework, or a Time Machine rewrite.

## Reproduce first

On a real Windows run, identify which layer actually fails:

1. current Viewer root/session is wrong or stale;
2. `fs.watch` does not emit expected events;
3. SSE connection/event handling is broken;
4. tree refresh and artifact-session refresh diverge;
5. file-extension filtering excludes the user's changed output;
6. another concrete cause.

Collect evidence before changing production code.

## Existing seams to preserve

- `src/viewer/server.cjs`
  - recursive `fs.watch`;
  - 3s polling fallback;
  - SSE broadcast;
  - artifact diff / Time Machine;
  - project root + extra roots.
- `src/viewer/public/app.js`
  - EventSource realtime updates;
  - tree/artifact/current-file refresh.
- `src/main/viewer-context-sync.js` + `syncViewerConversationContext()`
  - active Kimi/CloudCLI context -> Viewer root/session.

## Suspicious but not pre-decided

`WATCHED_EXTENSIONS` only covers MD/JSON/HTML/Mermaid for artifact scheduling while Viewer dev mode can render additional code/text extensions. Verify whether this explains the user's symptom; do not broaden blindly if the actual root cause is context/SSE/watcher state.

## Required acceptance

Use a fixture/current real project and prove without manual refresh:

- create MD -> tree/artifact visible;
- modify MD -> open preview updates and artifact diff appears;
- delete MD -> tree/artifact coherent;
- modify JSON -> realtime update;
- modify one representative code/text file in dev mode if that class is intended to be realtime-visible;
- SSE/live indicator remains connected;
- current Viewer root matches active engine project after Kimi <-> CloudCLI switching;
- Time Machine regression remains green.
