# 首次启动 Doctor 原型设计（仅文档）

> 目标：把“下载 → 启动 → 环境检查 → 打开任意引擎 → Viewer 展示首个产物”压缩成五分钟闭环。
> 本文件只描述设计，不包含实现代码。

## 背景

当前新用户启动 KCC 后，需要自行判断 Kimi Code CLI、Node.js 22、CloudCLI 是否可用。环境问题导致“打开就报错”，首次体验差，且报错信息往往不说明真正原因。

## 目标体验

启动后显示一个环境检查页，逐项给出结果与下一步：

```text
KCC 环境检查

✓ Windows 11 x64
✓ Kimi Code CLI 可用
✓ CloudCLI runtime 完整
✗ Node.js 22 未找到        [查看说明]  [安装 Node 22]

当前可使用 Kimi Code；安装 Node 22 后可启用 Claude Code / Codex。
```

## 检查项

| 检查项 | 通过条件 | 下一步 |
| --- | --- | --- |
| Windows 版本与架构 | Windows 10/11 x64 | 提示不支持的环境 |
| Kimi Code CLI | `kimi` 在 PATH 且 `kimi web` 可启动 | 给出安装指引 |
| Node.js 22 | `node -v` 为 22.x，ABI 127 | 给出安装/降级命令 |
| CloudCLI runtime | 随包依赖完整 | 提示重新安装或修复 |
| 必要目录/端口 | 应用数据目录可写、端口可监听 | 给出清理指引 |
| 诊断日志 | 可写入 `%APPDATA%\KCC Workbench\viewer-context.log` | 提示权限问题 |

## 行为

- 只读检查，不修改用户环境。
- 每个失败项给出与真实根因匹配的修复方式，而不是泛泛的“请检查”。
- 提供“重新检测”按钮。
- 提供“复制脱敏诊断报告”按钮，方便用户贴到 Issue。
- 检查通过后自动进入首页，不打断用户。

## 脱敏

诊断报告必须删除：

- Cookie、Token、认证头
- 账号、额度和账单信息
- 项目源码、系统提示词与 Git patch
- 用户名、本机绝对路径与会话标识

## 局限

- Doctor 只能检测，不能替代真实登录验收。
- 识别“Node 22 已安装但 ABI 不匹配”需要运行 CloudCLI 自检，可在后续版本实现。

## 验收标准

1. 干净 Windows 环境启动后能看到 Doctor。
2. 每个失败项都有明确修复指令。
3. 一键重新检测可用。
4. 诊断报告可复制且已脱敏。
5. 检查通过后能正常进入首页。
